# Тестирование django-shop

Здесь записано только то, что реально запускалось, с числами из логов. Стенд — один Linux-хост с Docker
(Compose v2, `DC="sudo docker compose"`), сеть хоста, порты 8098 / 8099 / 54317 / 54318.

## Что входит в раунд

`docker/round.sh` выполняет по порядку и останавливается на первом сбое:

1. `docker/check-repo.sh` — в git нет `var/`, `.env`, дампов, ключей, собранного CSS и литеральных паролей,
   секретов и токенов (в YAML пароль допустим только как `*_FILE: /run/secrets/…`);
2. сборка образов `web` и `tools`;
3. `ruff format --check .`, `ruff check .`, `mypy .` (strict + django-stubs), `manage.py check`,
   `makemigrations --check --dry-run`;
4. `npm run build:css` (Tailwind 4) и `npm run types:check` (tsc для e2e);
5. pytest на тестовом PostgreSQL 17 (порт 54318, tmpfs, `fsync=off`);
6. сайт (`web` + `nginx`), `migrate`, `seed_demo`, Playwright e2e (`--project=e2e`).

Скриншоты — отдельно: `seed_demo` и `npx playwright test --project=screenshots`.

## Playwright 1.65 (Chromium, на хосте)

- **e2e** — `e2e/purchase.spec.ts`, 1 тест, 33 вызова `expect(…)` в исходнике: гость добавляет товар в корзину →
  оформление требует входа → вход демо-покупателем (пароль из `var/demo-users.json`) → корзина гостя сохранилась →
  заказ «Новый», остаток 14 → 12 → «Отказ» → «Оплата отклонена», остаток остаётся 12 → «Оплатить ещё раз» →
  «Оплачен», заказ в «Моих заказах». Ретраев нет (`retries: 0`), принудительных кликов нет.
- **screenshots** — `e2e/screenshots.spec.ts`, 4 теста (покупатель и менеджер × 1440 и 390), 26 PNG в
  `docs/screenshots`; на каждом экране проверяется отсутствие горизонтальной прокрутки страницы.

## Что не проверяется

- Playwright в CI не запускается (только локально), браузер — только Chromium.
- В админке на 390 px таблицы списков прокручиваются внутри своего блока — это штатная вёрстка
  `django.contrib.admin`; горизонтальной прокрутки всей страницы нет.
- Нагрузочного тестирования нет; гонка за остатком проверяется двумя потоками в pytest.
